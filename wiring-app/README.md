# ⚡ ניהול חיווטים וארונות — אב־טיפוס

אב־טיפוס עובד של מערכת לניהול עבודות חיווט בארונות חשמל בתחנת משנה (תחמ״ש).

> **חשוב:** זהו אב־טיפוס להדגמה בלבד. **כל הנתונים במערכת מדומים** — אין בה שום מידע
> אמיתי של חברת החשמל או של כל גורם אחר, והיא פועלת **מקומית בלבד** על המחשב שלכם,
> ללא שליחת מידע לשירותים חיצוניים.

## מה נבנה

- **לוח בקרה** — התקדמות כללית, ארונות/כבלים/גידים, חריגות פתוחות, ארונות לא מעודכנים, פעילות אחרונה וחיפוש מהיר.
- **פרויקטים וסטי חיווט** — יצירת פרויקט, יצירת סט, העלאת מספר קובצי PDF, הפעלת "מיפוי סט החיווט" (מנוע הדגמה) ומעקב סטטוס מיפוי.
- **מסך בדיקת נתונים** — טבלה ניתנת לעריכה של השורות שחולצו, סימון שורות לא תקינות, תיקון, אישור שורה בודדת / כל התקינות, והזנה לפרויקט.
- **מסך ארונות** — כרטיסים או טבלה, צבעי סטטוס (ירוק הושלם / כתום בביצוע / אדום חריגה / אפור טרם התחיל / כחול ממתין לבדיקה), סינון וחיפוש.
- **מסך ארון** — פרטים, רשימת כבלים עם סינון, עובדים שביצעו, היסטוריית פעולות, הערות, דיווח חריגה וקוד QR להדפסה.
- **מסך כבל** — רשימת גידים עם תיבות סימון גדולות, סימון מרובה / הכל, הערות שינוי לכל גיד, דיווח חריגה, ואישור בדיקה סופית (בודק/מנהל בלבד).
- **חריגות ושינויים** — רשימה עם סינון, צירוף תמונה (שם קובץ בהדגמה), תגובה ואישור מנהל.
- **פתקי חיווט** — בחירת פרויקט/ארון/כבל/גידים, תצוגה מקדימה, גודל פתק, כמות עותקים, הדפסה בדפדפן / שמירה כ־PDF וייצוא CSV.
- **מסך ניהול** — התקדמות לפי ארון ולפי עובד, כבלים ממתינים לבדיקה, חריגות פתוחות, ארונות ללא עדכון ואירועים אחרונים.
- **התראות בתוך האפליקציה** — ארון הושלם, כבל ממתין לבדיקה, חריגה חדשה, ארון לא מעודכן, סט אושר.
- **כללי עסק** — כבל מושלם רק כשכל גידיו הושלמו; ארון מושלם רק כשכל כבליו נבדקו ואושרו; כל פעולה נרשמת בהיסטוריה עם שם העובד והתאריך; רק בודק/מנהל מאשרים חיווט סופי; רק מנהל מטפל בחריגות.

## טכנולוגיה

- **Next.js 16 + TypeScript** (App Router) — ממשק ו־API באפליקציה אחת.
- **Tailwind CSS 4** — עברית מלאה, RTL אמיתי, Responsive למחשב/טאבלט/טלפון.
- **SQLite (better-sqlite3)** — בסיס נתונים מקומי בקובץ `data/app.db`, ללא שרת חיצוני.
- **Vitest** — בדיקות ללוגיקת ההתקדמות וההרשאות.
- **qrcode** — יצירת קודי QR לארונות.

## התקנה

דרישות: Node.js 20 ומעלה.

```bash
cd wiring-app
npm install
```

## הפעלה

```bash
npm run dev        # סביבת פיתוח — http://localhost:3000
# או:
npm run build && npm start   # הרצת גרסת Production
```

בכניסה הראשונה נטענים אוטומטית נתוני הדוגמה (Seed). בחרו משתמש במסך הכניסה:

| תפקיד | משתמשים | הרשאות |
|---|---|---|
| עובד | יוסי לוי, דוד כהן, משה פרץ | סימון גידים, הערות, דיווח חריגות |
| בודקת | רונית אברהם | + אישור בדיקה סופית של כבלים |
| מנהל | אבי מזרחי | + תגובה ואישור חריגות, מסך ניהול |

## בדיקות ואיכות

```bash
npm test           # בדיקות יחידה (חישובי התקדמות, כללי סטטוס, הרשאות)
npm run typecheck  # בדיקת TypeScript
npm run lint       # ESLint
```

## איפוס נתוני הדוגמה

```bash
npm run db:reset
```

מוחק את `data/app.db` וטוען מחדש את נתוני הדוגמה: פרויקט "תחמ״ש לדוגמה",
"סט חיווט 01", 4 ארונות, 20 כבלים, 82 גידים, 5 משתמשים, 2 חריגות, הערות והיסטוריה.

## ייבוא נתונים אמיתיים מקובץ JSON

כדי לעבוד עם נתונים שחולצו משרטוט אמיתי **בלי לשמור אותם בקוד או ב־Git**:

1. מכינים קובץ בפורמט `wiring-app-import-v1` (ראו מבנה ב־`app/api/import/route.ts`) —
   פרויקט ← ארונות ← כבלים ← גידים עם מהדקי מקור ויעד.
2. נכנסים למסך **פרויקטים ← "📥 ייבוא מקובץ JSON"** (או ישירות `/import`).
3. בוחרים את הקובץ, רואים תצוגה מקדימה ומאשרים. אפשר לסמן ניקוי נתוני
   הדוגמה לפני הייבוא (המשתמשים נשמרים).

הקובץ עצמו אינו נשמר במערכת; הנתונים נטענים ל־`data/app.db` המקומי בלבד,
ותיקיית `data/` מוחרגת מ־Git. חזרה לנתוני הדוגמה: `npm run db:reset`.

## מה מדומה באב־טיפוס

- **חילוץ ה־PDF** — הקבצים שנבחרים אינם נקראים ואינם נשמרים; נשמרים רק שם וגודל.
  "מיפוי סט החיווט" מפעיל `DemoDocumentExtractionService` שמייצר נתוני חיווט
  דטרמיניסטיים לפי שם הקובץ, כולל שורות "שבורות" להדגמת מסך הבדיקה. הממשק
  `DocumentExtractionService` (ב־`lib/extraction/`) מופרד כך שבעתיד ניתן להחליפו
  במימוש אמיתי (OCR / AI ארגוני) ללא שינוי בשאר הקוד. המשתמש רואה בבירור שמדובר במנוע הדגמה.
- **התחברות** — בחירת משתמש מרשימה, ללא סיסמה. מיועד להדגמה בלבד.
- **תמונות בחריגות** — נשמר שם הקובץ בלבד.
- **התראות** — בתוך האפליקציה בלבד (אין שליחת SMS/דוא״ל).

## מה נדרש בעתיד למעבר למערכת אמיתית

1. **קבצי תוכניות אמיתיים** — קבלת קובצי ה־PDF חייבת להיעשות באישור הגורם המוסמך בארגון
   (מנהל הפרויקט / מחלקת תכנון / ממונה אבטחת מידע), ועיבודם צריך להתבצע רק על תשתית
   מאושרת של הארגון — לא בשירותי ענן חיצוניים. מנגנון החילוץ מוכן להחלפה דרך הממשק
   `DocumentExtractionService`.
2. **משתמשים ארגוניים** — חיבור ל־SSO/Active Directory ארגוני במקום התחברות ההדגמה,
   כולל ניהול הרשאות אמיתי.
3. **שרת ובסיס נתונים משותפים** — מעבר מ־SQLite מקומי לבסיס נתונים ארגוני כדי לאפשר
   עבודה מרובת משתמשים בו־זמנית.
4. **מדפסות** — חיבור למדפסות מדבקות תעשייתיות (Zebra וכדומה); כיום ההדפסה דרך הדפדפן.
5. **PWA וסריקת QR** — הוספת manifest ו־service worker לעבודה לא־מקוונת בשטח; נתיבי
   ה־QR (`/cabinets/[id]`) כבר בנויים כך שסריקה עתידית תפתח ישירות את הארון.
